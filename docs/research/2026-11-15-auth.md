## คำถาม
4. Better Auth: Google, email OTP, rate limit, adapter Drizzle+libSQL, การจำกัดสมัครด้วยโค้ดเชิญ
5. Google sign-in ใน PWA ที่ติดตั้งบน iOS
6. ส่ง OTP ผ่าน Gmail SMTP จาก Vercel

## คำตอบสั้น
- Better Auth 1.7.25 ทำได้ครบ: Google, email OTP (อายุ/จำนวนครั้งเดา/ความยาวตั้งได้), rate limit (แต่ค่าเริ่มต้นเก็บในหน่วยความจำ ใช้ไม่ได้จริงบน serverless ต้องย้ายไป database), session 60–90 วันตั้งได้ · ไม่มีปลั๊กอินโค้ดเชิญทางการ ใช้ `databaseHooks.user.create.before` ได้
- Google redirect ในแอป iOS ที่ติดตั้ง **มีความเสี่ยงจริง** (cookie แยกกับ Safari ทำให้ PKCE/state หาย) พบเฉพาะรายงานจากโปรเจกต์โอเพนซอร์ส ไม่มีเอกสาร Apple รองรับ ต้องทดสอบบนเครื่องจริง
- Gmail SMTP ใช้ได้ (ลิมิต 500/วัน, ต้อง 2-Step + app password, พอร์ต 465/587 เปิดบน Vercel) แต่ Vercel แนะนำ HTTP API มากกว่า และ Google เองไม่แนะนำ app password

## B5. Google sign-in ใน PWA ติดตั้งบน iOS

| ข้อเท็จจริง | แหล่ง | ความมั่นใจ |
|---|---|---|
| Home Screen web app มี cookie/storage แยกจาก Safari · เมื่อเด้งไป origin อื่น (accounts.google.com) iOS เสนอให้เปิดใน Safari/ sheet แยก · callback ไปลงที่ Safari ซึ่งไม่มี cookie PKCE/state จากแอป → ล้มเหลว หรือ login สำเร็จแต่ในแอปยังไม่ล็อกอิน | [bulwarkmail #1267](https://github.com/bulwarkmail/webmail/issues/1267), [FlashCardApp PR #19](https://github.com/Naijei1/FlashCardApp/pull/19) | รอง (ไม่ระบุรุ่น iOS ใน #1267; PR #19 ไม่ได้รายงานผลทดสอบเครื่องจริง) |
| แนวทางที่ชุมชนใช้: เก็บ PKCE/state ฝั่งเซิร์ฟเวอร์ผูกกับ `state` แล้วแลกเป็น handoff cookie ในแอป · ใช้โค้ดสั้นยืนยันข้ามแอป · เปิดหน้าต่างในแอปจากการแตะ · ให้ล็อกอินใน Safari ก่อนติดตั้ง (session ไม่ข้ามไปแอป) · ซ่อนปุ่ม Google ใน standalone | PR/issue หลายรายการจากการค้นหา (ดู 2 ลิงก์ข้างบน) | รอง ยังไม่มีรายการใดยืนยันว่าแก้ได้จริง |
| iOS 26: ทุกเว็บที่เพิ่มลง Home Screen เปิดเป็น web app โดยปริยาย (ผู้ใช้ปิดได้) ไม่ต้องมี manifest | [WebKit Safari 26.0](https://webkit.org/blog/17333/webkit-features-in-safari-26-0/) | ทางการ |
| ไม่พบเอกสาร Apple/WebKit ที่อธิบายการ redirect นอก scope ของ Home Screen web app หรือแนวทางที่แนะนำ | ค้นหาแล้ว | ไม่ได้ |
| Better Auth เก็บ OAuth state/PKCE ที่ไหน (cookie หรือ DB) | หน้า oauth ไม่ระบุ | ไม่ได้ |
| Better Auth รองรับ ID token flow (ล็อกอินโดยไม่ redirect) — เป็นทางเลี่ยงที่ควรทดสอบ แต่ไม่ได้ตรวจว่าปุ่ม Google ฝั่งไคลเอนต์ทำงานใน standalone iOS ได้หรือไม่ | [google](https://www.better-auth.com/docs/authentication/google) | ทางการ (มีโหมด) · ไม่ได้ (ใช้ได้บน iOS standalone) |

## B6. Gmail SMTP

| ข้อเท็จจริง | ค่า | แหล่ง | ความมั่นใจ |
|---|---|---|---|
| ลิมิตบัญชีทั่วไป | เกิน 500 อีเมล/วัน หรือ 500 ผู้รับ/ข้อความ จะติดลิมิต · ปลดเองใน 1–24 ชม. | [Gmail Help 22839](https://support.google.com/mail/answer/22839) | ทางการ |
| ผู้รับต่อข้อความผ่าน SMTP | 100 (Workspace) · ของบัญชีฟรีมีแต่แหล่งรอง | [Workspace limits](https://knowledge.workspace.google.com/admin/gmail/gmail-sending-limits-in-google-workspace) | ทางการ (Workspace) · รอง (ฟรี) |
| App password | ต้องเปิด 2-Step Verification · Google เขียนว่า "ไม่แนะนำและไม่จำเป็นในกรณีส่วนใหญ่" · เปลี่ยนรหัส Google แล้วถูกเพิกถอน | [Gmail Help 185833](https://support.google.com/mail/answer/185833) | ทางการ |
| ที่อยู่/พอร์ต SMTP ของ Gmail | ไม่พบในหน้าที่เปิด | — | ไม่ได้ |
| ข้อกำหนดการใช้ | Gmail Program Policies ห้ามสแปม/อีเมลไม่พึงประสงค์ และห้าม "automate the Gmail interface" · ไม่พูดถึง SMTP หรืออีเมลธุรกรรมจากแอปโดยตรง | [Gmail policies](https://support.google.com/mail/answer/16734397) | ทางการ · ตีความว่าอนุญาตหรือไม่ **ไม่ได้ชัดเจน** |
| Vercel บล็อกพอร์ต | บล็อกเฉพาะพอร์ต 25 · 465/587 เปิด | [Vercel KB](https://vercel.com/kb/guide/sending-emails-from-an-application-on-vercel) | ทางการ |
| nodemailer บน Vercel | ใช้ได้บน Node.js runtime ที่ 465/587 ถ้า `await` การส่ง แต่ Vercel แนะนำ HTTP API (Resend/SendGrid/Postmark/SES) มากกว่า · ถ้าปิด Fluid compute จะมีเพดาน 10 วิ (Hobby) | เดียวกัน | ทางการ |

ข้อขัดแย้ง: Better Auth บอกว่า **อย่า await** การส่งเมล (ใช้ `waitUntil`) แต่ Vercel บอกว่า SMTP ต้อง **await** ไม่งั้นอาจส่งไม่สำเร็จ → ใช้ `waitUntil` ของ Vercel ครอบ promise ที่ await ภายใน (ข้อเสนอ ยังไม่ได้ทดสอบ)

## ผลต่อโปรเจกต์
- PRD ข้อ 5 (E1 เกณฑ์รับงาน): "OTP หมดอายุ 10 นาที, เดาผิดเกิน 5 ครั้ง" ตั้งได้ (ค่าเริ่มต้น 5 นาที/3 ครั้ง ต้องกำหนดเอง) · "จำกัดต่ออีเมล/ต่อ IP" ต้องเขียนกฎเอง เพราะ Better Auth จำกัดตามเส้นทาง+IP
- ADR auth ต้องระบุ rate limit `storage: "database"` (หรือ secondary storage) มิฉะนั้นบน Vercel ตัวนับไม่ถูกแชร์ระหว่าง instance (อนุมานจากข้อความ "ไม่เหมาะ serverless")
- PRD ข้อ 8 ความเสี่ยง Google บน iOS: ยืนยันว่าเป็นความเสี่ยงจริง และ OTP สำรองเป็นทางรอด (ต้องแน่ใจว่า OTP ใช้ได้ใน standalone เพราะไม่ออกนอก origin)
- สิ่งที่ Architect ต้องตัดสิน: โค้ดเชิญใช้ hook เอง หรือปลั๊กอินชุมชน (alpha) · สลับผู้ส่งเมลเป็น HTTP API ภายหลังได้ง่ายหากห่อ `sendVerificationOTP` ไว้ชั้นเดียว
- ลิมิต 500/วัน พอสำหรับกลุ่มเล็ก แต่ถ้าโตเป็นร้อยคนและ session 90 วัน ควรประเมินใหม่

## ยังไม่รู้
- Better Auth + libSQL ใช้งานร่วมกันได้จริงไหม (ควรให้ dev สร้าง spike ทดสอบ) · วิธีส่งโค้ดเชิญเข้า hook
- iOS รุ่นปัจจุบันจัดการ redirect Google ใน standalone อย่างไรกันแน่ · ต้องทดสอบเครื่องจริงใน R1
- Google อนุญาตการส่งอีเมลธุรกรรมอัตโนมัติจากบัญชีส่วนตัวหรือไม่ (นโยบายไม่ได้ห้ามชัด ไม่ได้อนุญาตชัด)
