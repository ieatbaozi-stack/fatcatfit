# ลิงก์ Google Maps ที่ควรรับ (CR3 D1)

เข้าถึงเมื่อ 2026-11-24

## คำถาม
1. ปุ่มแชร์ของ Google Maps ให้ลิงก์รูปแบบใดจริง และ `goo.gl/maps` ยังใช้ได้ไหม
2. ลิงก์ยาวทางการมีรูปแบบใดบ้าง โดเมนประเทศ (`google.co.th`) มีจริงไหม
3. allowlist ที่ควรใช้

## คำตอบสั้น
- รูปยาวทางการระบุเฉพาะ host `www.google.com` path `/maps/...` (ยืนยันจากเอกสารทางการ)
- `maps.app.goo.gl` เป็นลิงก์ย่อของปุ่มแชร์ตามที่คนทั่วไปรู้ แต่เอกสารทางการที่เปิดได้วันนี้ **ไม่ระบุชื่อโดเมนนี้** (ยืนยันไม่ได้จากเอกสารทางการ)
- Google บอกว่า goo.gl ที่สร้างจากแอป Google เช่นการแชร์ใน Maps "ยังใช้งานต่อ" แต่ไม่ได้เอ่ยถึง `goo.gl/maps` ตรงๆ

## ตารางข้อเท็จจริง
| ข้อเท็จจริง | แหล่ง | ความมั่นใจ |
|---|---|---|
| Maps URLs ทางการมี 5 แบบ ทั้งหมดใช้ `https://www.google.com/maps/...` และต้องมี `api=1`: `/maps/search/?api=1&query=`, `/maps/dir/?api=1`, `/maps/@?api=1&map_action=map\|pano\|shortlist` | [Maps URLs](https://developers.google.com/maps/documentation/urls/get-started), [guide](https://developers.google.com/maps/documentation/urls/guide) | ยืนยันจากเอกสารทางการ |
| เอกสาร Maps URLs ไม่พูดถึงลิงก์ย่อ โดเมนประเทศ และ `maps.google.com` เป็นรูปลิงก์ | หน้าเดียวกัน | ยืนยันจากเอกสารทางการ (ว่าไม่มีการระบุ) |
| ลิงก์ goo.gl ที่สร้างจากผลิตภัณฑ์ Google เช่นแชร์ใน Maps "will continue to function" | [Google Developers Blog](https://developers.googleblog.com/en/google-url-shortener-links-will-no-longer-be-available/) | ยืนยันจากเอกสารทางการ |
| อัปเดต 2025-08-01: ไม่ปิด goo.gl ทั้งหมดวันที่ 2025-08-25 แล้ว ปิดเฉพาะลิงก์ที่ไม่มีการใช้งานปลายปี 2024 และขึ้นข้อความเตือน | บล็อกเดียวกัน | ยืนยันจากเอกสารทางการ |
| บล็อกไม่เอ่ยถึง `maps.app.goo.gl` และ `goo.gl/maps` ตรงๆ | บล็อกเดียวกัน | ยืนยันจากเอกสารทางการ (ว่าไม่มีการระบุ) |
| Help หน้าแชร์ (คอมพิวเตอร์) ไม่ระบุรูปแบบลิงก์ที่ได้ และหน้า Android/iOS ที่เปิดอ่านได้ไม่บอกโดเมน | [Maps Help 144361](https://support.google.com/maps/answer/144361) | ยืนยันจากเอกสารทางการ (ว่าไม่มีการระบุ) |
| ตัวเลือก "Short URL" ใน Link to this map ให้ลิงก์สั้นกว่า (ไม่ระบุโดเมน) | ผลค้นหาสรุปจาก Maps Help | จากแหล่งรอง |
| แชร์จาก Maps ได้ `maps.app.goo.gl/<id>` | ความเห็นผู้ใช้ในแหล่งรอง และความรู้ทั่วไป ไม่ได้เปิดดูลิงก์จริง | จากแหล่งรอง |
| โดเมนประเทศ `google.co.th/maps` เกิดจริงไหม | ไม่มีแหล่งทางการยืนยัน | ยืนยันไม่ได้ |
| `goo.gl/maps/...` (รุ่นเก่า) ยังใช้ได้ไหม | บล็อกไม่เอ่ยตรงๆ ไม่ได้ทดลองเปิดลิงก์ | ยืนยันไม่ได้ |

## ข้อเสนอ allowlist (ให้ Lead/boss ตัดสิน)
ตรวจด้วย `new URL()` แล้วเทียบ `hostname` แบบเท่ากันทั้งสตริง (ไม่ใช้ endsWith/includes) · `protocol === "https:"` · ไม่มี username/password ใน URL · port ว่างหรือ 443 · ตัดความยาวรวม เช่น 2048

| host (เท่ากันเป๊ะ) | path | หมายเหตุ |
|---|---|---|
| `maps.app.goo.gl` | `/<id>` ไม่ว่าง | ลิงก์แชร์ปัจจุบัน (ชั้นแรก) |
| `www.google.com` | ขึ้นต้น `/maps/` | รูปยาวทางการ |
| `google.com` | ขึ้นต้น `/maps/` | ทางเลือก (ไม่ยืนยันว่าเกิดจริง) |
| `maps.google.com` | ทุก path | ลิงก์เก่าที่พบทั่วไป (ไม่ใช่ทางการใน Maps URLs) |
| `goo.gl` | ขึ้นต้น `/maps/` | ลิงก์รุ่นเก่า รับหรือไม่ boss ตัดสิน |

ไม่แนะนำรับ: `google.co.th` และโดเมนประเทศอื่น (ยืนยันไม่ได้) · host ที่ใส่ port ผิดปกติ · `http:`

## ผลต่อโปรเจกต์
- ถ้า contract ระบุ allowlist ต้องเขียนเป็น "host เท่ากันเป๊ะ" ไม่ใช่ suffix match เพื่อกัน `google.com.evil.com` และ `evilgoogle.com`
- ลิงก์ย่อ (`maps.app.goo.gl`, `goo.gl`) เป็น redirect ไปปลายทางที่ไม่รู้ล่วงหน้า: ถ้าเซิร์ฟเวอร์ไม่ตามไปเปิด (แนะนำ) ก็แค่เก็บและแสดงเป็นลิงก์ ผู้ใช้เป็นคนกดเอง ต้องเปิดด้วย `rel="noopener noreferrer"` และไม่ fetch ฝั่งเซิร์ฟเวอร์ (กัน SSRF)
- ถ้าอยากดึงพิกัดหรือชื่อสถานที่จากลิงก์ ลิงก์ย่อทำไม่ได้โดยไม่ตาม redirect

## สิ่งที่ยังไม่รู้
- เอกสารทางการไม่ยืนยันชื่อโดเมน `maps.app.goo.gl` และพฤติกรรมของ `goo.gl/maps` ในปัจจุบัน
- โดเมนประเทศ (`google.co.th`) ที่ผู้ใช้ไทยอาจเจอจากการคัดลอก URL ในแถบเบราว์เซอร์
- รูปลิงก์ที่แอป Android/iOS ให้จริงตอนนี้ (ควรให้ boss คัดลอกตัวอย่างจากมือถือมาดูเฉพาะ host ไม่ต้องส่ง id)
