# iOS PWA (ติดตั้งที่หน้าจอโฮม): ที่เก็บข้อมูล, vibrate, เสียง, timer ตอนจอดับ

วันที่เปิดดูทุกแหล่ง: 2026-11-24 · รอบ R3a (`R3_LOGGING_CONTRACT.md`) · ขอบเขต iOS/iPadOS 16.4 ถึงรุ่นปัจจุบัน

## คำตอบสั้น
1. ข้อมูล IndexedDB/localStorage ของแอปที่ติดตั้งหน้าจอโฮม **ไม่ถูกลบตามกฎ 7 วัน** (ได้รับยกเว้น) แต่ยังถูก evict ได้เมื่อพื้นที่เครื่องตึง/เกิน quota เพราะเป็น best-effort
2. `navigator.storage.persist()` **มีใน iOS** ผลคืนเป็น true/false ตามฮิวริสติกของ WebKit (เช่น เปิดเป็น Home Screen app) ถ้าเป็น persistent จะไม่ถูก evict อัตโนมัติ
3. `navigator.vibrate` **ไม่รองรับ** บน iOS Safari/PWA ทุกรุ่นที่ caniuse ระบุ
4. Web Audio ต้องสร้าง/`resume()` AudioContext ในท่าทางของผู้ใช้ก่อน · ดีฟอลต์เสียงจะ **ถูกปิดเมื่อสวิตช์เงียบเปิด** วิธีแก้คือ `navigator.audioSession.type = "playback"` (แหล่งทางการยืนยันไม่ครบ) · หลังจอล็อกเสียงไม่เล่นแน่นอน
5. จอดับ/แอปไปเบื้องหลัง JS ถูกพักและ timer หยุด → ต้องคำนวณจาก timestamp · `visibilitychange` ยืนยันได้ว่าเกิดตอนสลับแอป แต่ตอนล็อกจอไม่การันตี

## ผลต่อโปรเจกต์
- **เก็บข้อมูลบันทึก**: IndexedDB ใช้ได้ในแอปที่ติดตั้ง ไม่โดนกฎ 7 วัน แต่ **ไม่ใช่ที่เก็บถาวรเด็ดขาด** → ต้องมี source of truth ฝั่งเซิร์ฟเวอร์/ซิงก์ และ outbox ที่ยังไม่ซิงก์ต้องไม่หายเงียบ (เตือนผู้ใช้ถ้าค้างนาน) · เรียก `persist()` ตอนติดตั้งแล้วเป็นการเสริม ไม่พึ่ง และรับมือ `QuotaExceededError`
- **ผู้ใช้เปิดผ่านแท็บ Safari (ไม่ติดตั้ง)** โดนกฎ 7 วัน → ข้อมูลที่ยังไม่ซิงก์อาจหาย ควรมีข้อความแนะนำติดตั้งหรือซิงก์เร็ว
- **สั่น**: ห้ามพึ่ง `navigator.vibrate` บน iOS ต้องมีทางเลือก (เสียง/ภาพ/ข้อความ) และ feature-detect
- **เสียง**: สร้าง/resume AudioContext จากการแตะของผู้ใช้ (เช่น ปุ่มเริ่มจับเวลา) · ตั้ง `audioSession.type = "playback"` ถ้ามี (feature-detect) แต่ต้องบอกผู้ใช้ว่าสวิตช์เงียบอาจทำให้ไม่ได้ยิน ถือเสียงเป็นส่วนเสริม ไม่ใช่ตัวเดียวที่แจ้งเตือน · เสียงตอนจอล็อกอย่าสัญญา
- **จับเวลา**: บันทึกเวลาเริ่ม/สิ้นสุดเป็น timestamp (`Date.now()` หรือ epoch) แล้วคำนวณเวลาที่เหลือจาก timestamp ทุกครั้งที่วาด UI ห้ามนับด้วยการ +1 ใน setInterval · ฟังทั้ง `visibilitychange` และ `pageshow`/`focus` เพื่อคำนวณใหม่ตอนกลับมา ไม่พึ่งว่าจะมี event ตอนล็อกจอ
- **Wake Lock**: ถ้าอยากให้จอไม่ดับระหว่างจับเวลา ใช้ได้เฉพาะ iOS 18.4+ ต้อง feature-detect และมี fallback
- PRD/ADR ที่ต้องปรับ: ข้อกำหนดแจ้งเตือนตอนจับเวลาครบ (ห้ามสัญญา haptic/เสียงตอนล็อกจอบน iOS) และข้อกำหนดซิงก์/ที่เก็บในเครื่อง

## สิ่งที่ยังไม่รู้
- พฤติกรรมสวิตช์เงียบกับ Web Audio และ `audioSession` ในรุ่นปัจจุบัน (iOS 18/26) ยืนยันจากเอกสารทางการไม่ได้ ต้องทดสอบบนเครื่องจริง
- `visibilitychange` ตอนล็อกจอใน PWA ปัจจุบันยืนยันไม่ได้ (bug ปี 2020 ขัดกับสิ่งที่ควรเป็น)
- เลขรุ่น Safari ที่เริ่มรองรับ `persist()` ยืนยันไม่ได้ (ตาราง MDN ดึงไม่ได้) และ quota ของ iOS 16.4-16.x
- การลบแอปแล้วข้อมูลหายหรือไม่ (ไม่ได้ค้นตรง)
- Apple developer docs (developer.apple.com) เปิดได้เฉพาะหัวข้อทั่วไป ไม่พบหน้าทางการเฉพาะเรื่องสวิตช์เงียบ
